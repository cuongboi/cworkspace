# cworkplace

A self-hosted clone of **Facebook Workplace**: one company per deployment, with:

- **Feed & groups**: public, closed and secret groups (plus an "All company" group), posts with polls, events, attachments and @mentions, comments with replies, reactions
- **Chat**: 1:1 and group conversations with typing indicators, read receipts and presence
- **Calls**: audio/video calls with screen share (WebRTC mesh, up to 6 people)
- **Calendar**: meetings, events, out-of-office and reminders, RSVP, recurrence, video meetings
- **Notifications** stored and pushed live, **people directory**, **search**, and **admin settings** (people, roles, deactivation, email invitations)

Access control (group privacy, chat membership, admin and RBAC overrides) is enforced by ZenStack access policies on the server and covered by tests.

Under the hood it is a full-stack TypeScript monorepo: a **React SPA** (`apps/web`) backed by a **Bun + Elysia API** (`apps/api`) with **ZenStack** (policy-aware ORM on PostgreSQL) and **better-auth** for authentication. In production the API compiles to a single binary that also serves the built web app.

## Getting started

### Prerequisites

- Bun 1.4.x and Node ≥ 24
- PostgreSQL (or Docker: `docker compose up -d` starts MiniStack (Postgres via RDS + S3 for files), StackPort and coturn for calls)

### Setup

```bash
bun install
cp .env.example .env            # then fill in the values below
docker compose up -d            # optional: MiniStack (+ bucket, RDS Postgres), StackPort, coturn
bun --cwd apps/api run db:push  # create/update tables from schema.zmodel
bun run dev                     # starts api (:3000) and web (:5173) via Turborepo
```

Open http://localhost:5173, and sign up: the first account becomes the instance admin and everyone lands in the "All company" group. The Vite dev server proxies `/api`, `/ws` and `/openapi` to the API on port 3000, so cookies stay same-origin. Without `RESEND_API_KEY`, invitation links are printed in the API console.

### Environment variables (root `.env`)

| Variable                                                                                | Required              | Default                 | Purpose                                                                         |
| --------------------------------------------------------------------------------------- | --------------------- | ----------------------- | ------------------------------------------------------------------------------- |
| `DATABASE_URL`                                                                          | yes                   | —                       | PostgreSQL connection string                                                    |
| `BETTER_AUTH_SECRET`                                                                    | yes                   | —                       | Secret for signing sessions/tokens (use a long random string)                   |
| `BETTER_AUTH_URL`                                                                       | no                    | `http://localhost:3000` | Public base URL of the API                                                      |
| `BETTER_AUTH_BASE_PATH`                                                                 | no                    | `/api/auth`             | Mount path for auth routes                                                      |
| `WEB_ORIGIN`                                                                            | no                    | `http://localhost:5173` | Allowed CORS / trusted origins (comma-separated)                                |
| `APP_URL`                                                                               | no                    | first `WEB_ORIGIN`      | Public web URL used in emailed links                                            |
| `RESEND_API_KEY` / `MAIL_FROM`                                                          | no                    | —                       | Email delivery (invitations, password reset); printed to the console when unset |
| `S3_ENDPOINT` / `S3_REGION` / `S3_BUCKET` / `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` | for uploads           | —                       | Private S3-compatible bucket for attachments, avatars and covers                |
| `STUN_URLS` / `TURN_URLS` / `TURN_SECRET`                                               | for calls across NATs | Google STUN             | WebRTC ICE servers; TURN credentials are issued per user and expire             |
| `VITE_BETTER_AUTH_URL`                                                                  | no                    | —                       | Auth URL exposed to the web app                                                 |
| `DB_LOG_QUERIES`                                                                        | no                    | `false`                 | Set `true` to log SQL queries                                                   |

## API overview

| Endpoint                         | Description                                                                                                                   |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `GET /health`                    | Liveness check                                                                                                                |
| `GET\|POST /api/auth/*`          | better-auth routes (sign-in, sign-up, session, password reset, admin, JWKS…)                                                  |
| `POST /api/execute`              | Run an allowlisted ORM operation `{ model, operator, args }` under the caller's access policies (auth required, 300/min)      |
| `POST /api/uploads`              | Create an attachment and a presigned upload to the bucket                                                                     |
| `GET /api/files/:id`             | Access-checked redirect to a short-lived download URL                                                                         |
| `POST /api/conversations/direct` | Find or create the 1:1 conversation with a colleague                                                                          |
| `GET /api/rtc/ice`               | STUN/TURN servers with temporary TURN credentials                                                                             |
| `WS /ws`                         | Authenticated realtime channel: live updates, presence, typing, call signaling (see `packages/shared/src/realtime-events.ts`) |
| `GET /openapi`                   | Interactive API docs (Scalar), including auth routes                                                                          |
| `GET /*`                         | Serves the built SPA from `src/public` (unknown `/api/*` paths return a JSON 404)                                             |

All JSON responses use one envelope: success → `{ "data": ... }`, failure → `{ "error": { "message", "code", "details?" } }` with codes such as `UNAUTHORIZED`, `FORBIDDEN`, `INVALID_INPUT`, `NOT_FOUND`, `CONFLICT`, `INVALID_STATE`, `INTERNAL`.

## Development guidelines

### Data model & access control

- `apps/api/zenstack/schema.zmodel` is the single source of truth. After editing it, run `bun run db:generate` then `bun run db:push` (in `apps/api`). Never edit the generated `zenstack/*.ts` files.
- Define access rules with `@@allow` / `@@deny` in the zmodel. The policy plugin denies by default, so **a model with no rules cannot be read or written through `/api/execute`**.
- Use the right DB client (`src/lib/db.ts`):
  - `authDb.$setAuth(user)` — policy-enforced; this is what `userDb` in route handlers is. Use it for anything driven by user input.
  - `db` — bypasses policies. Only for trusted server code (auth adapter, background jobs, seeding). Never expose it to `/api/execute`.

- Use RBAC permission for table like:

```
  permission = [
      {model: "User", actions: ["create", "update", "delete"]}
  ]
```

RBAC with condition for model like:

````
model ExampleModel {
    id ...
    ...
    @@allow('all', auth().permissions?[model == currentModel() && currentOperation() in actions])
    ...
}
``
- When create new model, remember to use `@@map('<table_name>')` as lower case table name.

### Backend (apps/api)

- Read env vars only through `env` from `@/env`; add new required keys there and to `.env.example`.
- Protect routes with the auth macro: `.use(authMacro).get(path, handler, { auth: true })`. The handler then receives `user`, `session`, and `userDb`.
- Group routes as named Elysia plugins under `src/routes/` (`new Elysia({ name: "routes.xxx" })`) and register them in `src/index.ts` **before** `staticPlugin`, whose `/*` wildcard would otherwise shadow them.
- Validate request bodies with Elysia's `t` schemas and add `detail: { tags, summary }` so routes appear in the OpenAPI docs.
- Throw `HttpError` helpers from `@/lib/errors` (`badRequest`, `notFound`, `forbidden`, `conflict`, `invalidState`…). The global error handler converts them — and ZenStack/Postgres errors — into the standard envelope. Never return raw SQL or stack traces.
- For API queries involving the database that use the `/execute` endpoint—routed through the `@apps/web/lib/api-client.ts` file—the queries follow a syntax similar to Prisma ORM.
- For task related websocket communication, write code in `./apps/api/src/websocket/**/*`.

### Frontend (apps/web)

- Talk to the API **only** through `src/lib/api-client.ts`; don't call `fetch` from components.
  - Data access: `db.<model>.<operation>(args)` — fully typed with the ZenStack types, executed on the server via `/api/execute`.
  - Custom workflow routes: `api.get<T>(path)` / `api.post<T>(path, body)`.
  - Failures throw `ApiError` with a typed `code`; branch on `code`, not on message text.
- Auth: use `authClient` from `src/lib/auth-client.ts`. Wrap protected routes with `<RequireAuth />` and guest-only pages with `<GuestOnly />` in `src/router.tsx`.
- Keep filter/pagination state in the URL with `nuqs` (see `src/lib/search-params.ts`).
- Add UI primitives with `bunx shadcn@latest add <component>` (lands in `src/components/ui`). Import via the `@/` alias and compose classes with `cn()` from `@/lib/utils`.

### Code style

- TypeScript everywhere; avoid `any` outside framework glue.
- Run `bun run lint` and `bun run check-types` before committing; format with `oxfmt` (api) / Prettier (web).
- Comments explain *why*, not *what*.

## Build & deploy

```bash
bun --cwd apps/web run build   # builds the SPA into apps/api/src/public
bun --cwd apps/api run build   # compiles apps/api/server (single binary)
./apps/api/server --host 0.0.0.0 --port 3000
````

The binary serves the API, auth, WebSocket, and the SPA from one origin. It still needs the environment variables above at runtime.

## Development flow

- Checking database: read @apps/api/zenstack/schema.zmodel to understand the database schema.
- Updating or creating a table then run `bun --cwd apps/api run db:push` to update/create the table in the database.
- Write/update websocket communication related tasks: write/update code in `./apps/api/src/websocket/*`.
- Write/update component related tasks: write/update code in `./apps/web/src/components/*`.
- Write/update route related tasks: write/update code in `./apps/web/src/routes/*`.
- When planning, please create mermaid diagram to describe the architecture.
